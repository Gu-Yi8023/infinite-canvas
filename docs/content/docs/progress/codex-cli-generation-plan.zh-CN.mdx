# Codex CLI 生成能力改造规划

状态：代码已实施，飞牛实机验收待完成。本文补充[本地 Agent 接入规划](/zh-CN/docs/progress/local-agent-integration-plan)；实际部署步骤见 [NAS 部署指南](/zh-CN/docs/overview/nas)，可测试变更见[待测试](/zh-CN/docs/progress/pending-test)。

已增加 HTTPS 单用户网关、用户确认的固定 7 天登录、私有 worker、受控音频适配、Codex 生成分流、固定目标及产物恢复。已用项目实际锁定的 CLI `0.146.0` 核对 stdio、permissions profile 和 `imageGeneration.savedPath` 协议，并完成本地定向行为测试；尚未执行 Docker 构建、真实账号生成、飞牛沙箱及 OpenClash 实机验收。图片迁移须待真实输出验证后才能计为验收完成。

## 目标与范围

用户已确定：项目主要部署在家庭 NAS 的 Docker 中，通过局域网访问，基本只有用户本人使用，不做家庭成员权限隔离，使用一个 Codex 执行账号；NAS 另有 OpenWrt 虚拟机，内部 OpenClash 提供网络代理。对话、文本和图片使用 Codex；音频另接其他 API；视频暂时不用，保留以后接入其他 API Key 的位置。

将 Canvas Agent 改为 NAS 内部执行服务，应用入口保留单用户访问认证，可复用 NAS 已有的认证网关。应用认证与 Codex 登录分开：前者防止未授权访问，后者承担模型调用及额度。不实现成员管理、管理员/成员角色、按用户 owner 隔离或用户间访问控制；通过认证的设备使用同一应用空间。

改用 CLI 表示由本地 Codex 管理模型访问，并不表示模型离线运行、免费或无限使用。提示词和参考资料仍会发送给模型服务，实际能力与额度取决于登录账户和工作区。[官方认证说明](https://learn.chatgpt.com/docs/auth)区分 ChatGPT 登录和 API Key 登录，后者仍按 API 使用计费。

本次范围增加单用户入口认证、任务目标绑定、容器凭据保护和 OpenClash 出站接入。任务目标绑定用于防止多页面、多画布之间串结果，不是成员权限隔离。音频改为服务端受控适配，具体服务商、协议与 Key 待后续接入，不阻塞 Codex 改造。视频暂不开发或对接，保留代码、配置入口及已有媒体；音乐生成、语音转写、公网托管、桌面打包均不纳入首版。

当前画布和素材仍使用各浏览器的 localforage。把网页部署在 NAS 上不会自动把这些数据存到 NAS，也不代表不同设备已同步；本次先持久化服务器登录状态、任务目标及待接收产物，完整画布/素材的跨设备同步另行确定范围。

## 改造前的基础与缺口

| 位置 | 当前实现 | 本次工作 |
| --- | --- | --- |
| `canvas-agent/src/agent/codex-client.ts` | 启动 app-server，处理 JSON-RPC、模型、线程、流式消息、审批和取消 | 复用，补能力诊断与生成任务归属 |
| `canvas-agent/src/agent/codex.ts` | 会话管理、附件、历史与全局串行队列 | 区分侧边栏会话和独立生成任务，消除递归排队 |
| `web/src/services/api/canvas-agent.ts` | 浏览器访问本地 Agent 的入口 | 改用 NAS 同源应用 API，不向浏览器分发内部 Agent token |
| `web/src/services/api/image.ts` | `requestGeneration`、`requestEdit`、`requestImageQuestion` 直接调用 API 或模型脚本 | 在上层统一分流；文本节点、图像问答也须覆盖 |
| `web/src/services/api/audio.ts` | 浏览器持 Key 调用 `/audio/speech`，输出音频 Blob | NAS 版前端改调同源音频适配接口，Key 留在服务端 |
| `canvas-agent/src/canvas/operations.ts` | `canvas_generate_*` 创建生成节点并触发浏览器执行 | 文本/图片避免 API 回退或递归调用 Codex；音频继续独立 API |
| `canvas-agent/agent-instructions.md` | 默认要求调用 `canvas_generate_*`，只有明确要求才用内置 imagegen | 按实际后端和能力提供指令，不能只改提示词 |
| `web/src/components/agent/local-agent-panel.tsx` | 已接收 `image_generation` 完成事件、读取本机图片并导入画布 | 修 Windows 路径、产物识别、目标绑定和幂等恢复 |
| `Dockerfile`、`docker-compose*.yml`、`nginx.conf` | 只有 Nginx 静态站和端口映射，无 Agent、认证或持久卷 | 增加 NAS 专用服务编排，不能直接把当前镜像当完整服务器 |
| `canvas-agent/src/server/http.ts`、`canvas/session.ts` | 本机监听、共享 token、会话事件广播 | 增加单用户入口认证、固定 Origin、按任务和来源页面路由 |
| `canvas-proxy/index.js` | 无鉴权的任意 URL CORS 转发器，日志包含完整目标 URL | 不作为 NAS 的公开 API 代理使用 |

制定方案时确认的代码事实（以下为改造前状态）：

- Canvas Agent 通过自身依赖的 `@openai/codex` 启动 CLI，`canvas-agent/package.json` 锁定 `0.146.0`；不会自动使用 PATH 上的 Codex。本次只读查询中，PATH 上的 CLI 是 `0.163.0-alpha.11.2`，不能用它的能力代表项目运行时。
- 普通生成工具最终仍回到 `project.tsx` 中的 API 调用；已有 Codex 对话不代表所有生成已使用 Codex。
- `generatedImageSources` 目前识别 data URL 和 POSIX 图片路径，漏掉 Windows 盘符路径；它还递归扫描整个事件，不能可靠区分参考图与输出图。
- 自动导入依赖非 replay 的实时完成事件，不能据此保证刷新或断线后结果一定入库。
- `runCodexTurn` 使用全局串行队列。如果正在运行的 Codex 工具等待前端生成，而前端又把生成排进同一队列，会形成自等待。
- 当前 Origin 会向持有效 token 的新来源自动开放；`clientId` 仅是设备路由标识，不能代替入口认证。审批、停止和事件仍需关联正确任务，避免多页面操作串线。
- 当前镜像内没有 Node/Codex 执行器；把浏览器 Agent 地址留为 `127.0.0.1` 会连接访问者自己的设备，不会连接 NAS。

## 能力边界

| 能力 | 判断 | 工程处理 |
| --- | --- | --- |
| 侧边栏对话 | 已有 Codex 通道 | 完善登录诊断，复用线程和历史 |
| 文本生成、图片问答 | 可基于 Codex 对话与图片输入接入 | 将输出映射回文本节点；按实际模型能力开放输入 |
| 位图生成和编辑 | 官方 CLI 文档支持内置 imagegen；项目已有结果接收分支 | 先验证项目实际 CLI、账户、app-server 事件及产物，再开放生成按钮 |
| SVG 等代码绘图 | 可作为文本/代码生成后渲染 | 仅适用于对应图形需求，不作为位图能力的替代验收 |
| 可下载 TTS 音频 | 用户已选择其他 API | 保留独立渠道配置；未配置时仅提示音频不可用 |
| 视频生成 | 用户暂时不使用 | 暂不接入，保留以后配置 API Key 的入口 |

[官方生图文档](https://learn.chatgpt.com/docs/image-generation)说明 CLI 可通过自然语言或 imagegen 技能生成、编辑图片，并计入 Codex 使用额度。但这不能单独证明项目锁定版本的 app-server 已具备可用的返回契约；代码中的事件分支也不是实际成功证据。

[官方 Voice 文档](https://learn.chatgpt.com/docs/features/voice)介绍的是桌面语音交互，不足以证明可导出指定音色、格式和语速的 TTS 文件。[官方 TTS 文档](https://developers.openai.com/api/docs/guides/text-to-speech)提供的是独立 API 能力。

另外，[第三方 Sign in with ChatGPT 的预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)针对其 OAuth + Responses 路径，明确限制生图及部分音频能力；不能将这条路径与 Codex 内置登录和工具混为一谈。本方案使用 NAS worker 的 Codex 登录，不读取认证文件后自行拼接私有请求。

## 推荐架构

```text
用户浏览器
  -> LAN HTTPS 入口 + 单用户访问认证
  -> 静态前端 / 同源应用 API（会话、任务、产物）
       -> 内部 Canvas Agent + codex app-server（stdio）
            -> OpenWrt VM 的 OpenClash HTTP/mixed 入口 -> Codex 服务
       -> 受控音频 API 适配（独立服务端 Key）
            -> 按服务端出站配置 -> 音频服务

输出 -> NAS 任务产物目录 -> 任务与路径校验 -> 发起设备导入 localforage
视频保持未接入；Codex 失败不自动改走其他 API 渠道。
```

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)提供产品嵌入所需的会话、事件和审批机制，并支持按 CLI 版本导出协议。沿用现有 stdio 桥接；该接口仍有实验性与版本变动风险，因此锁定经过验证的版本，不把升级 CLI 当成自动修复。

## NAS 账号与访问安全

### 单用户访问入口

- 只保留一个受保护的应用入口，优先复用成熟的认证网关或 NAS 已有的认证集成，不新增成员管理或角色体系，不手写密码学或 OAuth。不假设 NAS 反向代理自带登录；所有 API、SSE、媒体读取与管理接口都必须实际经过认证。
- 浏览器不接收 OpenAI 密码、`auth.json` 或内部 Agent token。Codex 登录、渠道 Key、代理与技能配置由用户本人管理，无需额外区分管理员与成员。
- 认证由服务器验证，不能相信客户端自报的 `clientId` 或未经可信入口重写的身份请求头。不增加用户 owner 字段或按用户权限表；仍记录任务与来源页面、画布、节点及 thread/turn 的绑定。
- 审批、停止、模型工具回调和产物事件关联实际任务与目标页面，不能仅依赖当前活动标签页。认证设备使用同一会话空间，不承诺设备之间的数据私密隔离。
- 执行权限与允许访问的目录由服务端配置控制，生成请求不能通过传入 `full` 等参数隐式扩大权限；需要的审批沿用现有交互并由用户确认。
- 同源 HTTPS 使用 Secure、HttpOnly 会话 Cookie，配合适当的 SameSite、Origin/CSRF 校验；SSE 和图片请求不带长期 token 查询参数。会话撤销须使相关事件连接失效，内部 bridge token 仅服务端持有。
- 只信任明确配置的站点 Origin。关闭现有“持 token 即可加入 Origin”的行为；来源校验和 CORS 都不能替代用户认证。
- 当前节点插件在页面内执行，可能代登录用户发请求。只安装用户信任的插件、调用脚本与技能；HttpOnly 不能单独解决同源恶意脚本问题。

### Codex 登录与凭据

- 用户在最终 worker 容器内，使用与执行器相同的运行用户、实际 CLI 和专用 `CODEX_HOME` 完成官方登录。无浏览器环境优先验证 `codex login --device-auth`，需要账户允许设备登录；应用登录页面不收集 OpenAI 密码。
- 登录缓存放在只供 worker 访问的持久卷，允许 Codex 正常刷新；目录/文件限制为运行用户访问，禁止放入镜像、Git、前端静态目录或可公开下载的 NAS 共享目录。不要将可刷新缓存按只读 secret 挂载。[官方认证说明](https://learn.chatgpt.com/docs/auth)要求将认证缓存视为密码。
- 音频 Key 放在仅授予音频适配服务的 secret 文件或受保护配置中，浏览器只看到已配置状态，Codex worker 不挂载音频 Key。Compose secrets 是按服务挂载文件，并非对 NAS 管理员透明加密。[Docker secrets 文档](https://docs.docker.com/compose/how-tos/use-secrets/)
- 登录失效、额度不足时明确停止对应能力，不自动更换账号、尝试其他 Key 或重新提交生成。用户可以停用生成入口或撤销应用登录会话；各设备调用消耗同一 Codex 账号额度。
- NAS 管理员及控制容器的进程仍处于信任边界内。本方案按单用户可信设备使用设计，不作为陌生用户或公网服务。

### 执行容器和数据

- 前端、应用 API、Codex worker 按权限分离，只有 HTTPS 网关发布 LAN 端口；worker 和音频适配不单独发布。使用固定内部服务地址，区分监听地址、内部 MCP 回调地址和浏览器公开地址。
- 跨容器监听可以绑定容器内部接口，但不把它等同于允许局域网直连；只把所需服务加入对应 Docker 网络。既有 NAS 反代可接入同一受限网络。
- 使用非 root 运行用户、最小挂载和经过验证的沙箱。只开放任务工作目录及必要临时目录，禁止模型命令读取认证目录或无关 NAS 文件；限制无关命令、连接器及 MCP 工具。应用 worker 需要读取登录缓存，模型执行环境不应继承相同的任意文件访问能力。
- 不挂载 Docker socket、整个 NAS 数据盘、宿主家目录或 SSH 密钥；不默认使用 privileged、host network 或关闭全部安全策略。NAS 内核、CPU 架构及容器运行时是否支持所选 Codex 沙箱必须实测，失败不能自动降级为完全访问。[Codex 权限文档](https://learn.chatgpt.com/docs/permissions)
- 分别持久化应用会话状态、Codex 状态、任务目标、任务工作区及产物。复用合适的持久化方式，不新增成员数据库；避免用可变的 activeThreadId 替代任务目标记录。
- 产物经入口认证后按 ID 读取，并校验任务登记与文件路径，禁止任意绝对路径接口；禁用 NAS 上无意义的桌面“显示本地文件”入口。API 数据响应与日志不回传主机敏感路径、认证头、Cookie、Key 或带密钥的完整 URL。
- 备份需要区分业务产物与账号缓存；账号缓存备份须受保护，常规导出不包含凭据。备份恢复须验证任务目标和文件引用，不自动重跑尚未确认完成的生成。

## OpenWrt / OpenClash 网络方案

### 明确三种代理的职责

| 网络路径 | 用途 | 配置位置 |
| --- | --- | --- |
| 用户浏览器 → NAS HTTPS 入口 | 反向代理、登录、SSE 和资源访问 | NAS 反代/应用网关 |
| Codex / 音频适配 → OpenClash → 模型服务 | 运行时出站代理 | 对应容器和实际请求客户端 |
| Docker Engine / 镜像构建 → 镜像仓库或依赖源 | 拉镜像和安装依赖 | Docker daemon 与构建配置 |

Docker daemon 的代理不等于容器内程序的代理，反过来也不成立。[Docker daemon 代理](https://docs.docker.com/engine/daemon/proxy/)和[容器代理说明](https://docs.docker.com/engine/cli/proxy/)分别说明了这两层配置。

### 连接现有 OpenClash

- 首选容器显式连接 OpenWrt VM 的实际可达 IP 和 HTTP 或 mixed 端口，不改全家的默认网关。mixed 同时接受 HTTP(S) 与 SOCKS5；不使用控制面板端口或 redir/tproxy 端口作为 HTTP 代理。[代理端口文档](https://wiki.metacubex.one/config/inbound/port/)
- 端口与 IP 以用户部署为准，不预设为常见端口。容器内 `127.0.0.1` 是容器本身，不是 NAS 或 OpenWrt VM；验证虚拟交换机、路由和防火墙允许容器到 VM，允许来源以 VM 实际看到的地址为准。
- OpenClash 必须监听可达地址并允许该来源；通过允许列表/防火墙约束 NAS 服务的访问，按需要启用代理认证，禁止将代理和管理面板开放到公网。[外部访问配置](https://wiki.metacubex.one/config/general/)
- 为 Codex 进程及音频请求客户端配置 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`，具体是否生效必须按锁定版本验证；Node 的 fetch/axios、Codex 的登录、模型请求、图片下载及工具子进程不能假设行为一致。客户端不自动支持环境变量时使用成熟代理适配库，不能只设置变量便报告完成。
- 连接 HTTP/mixed 入口时，`HTTPS_PROXY` 的值通常也是 `http://OpenWrt地址:实际端口`，HTTPS 目标通过 CONNECT 建立 TLS 隧道；不因变量名为 HTTPS 就假设代理监听器提供 TLS。
- `NO_PROXY` 列出 loopback、确切内部服务名和必要的 NAS 本地目标；不使用 `*`，也不假设所有客户端都理解 CIDR。Codex 的 MCP 回调与应用内部请求必须直连内部地址，不经过 OpenClash。代理和服务目标由服务端配置，不接受生成请求任意覆盖。
- Codex 沙箱的网络代理负责约束工具命令，不能当成模型/认证请求的统一出口；不要把其本地监听 `proxy_url` 直接改成 OpenClash 地址。使用实际版本支持的上游代理配置，并分别验证各流量层。[权限网络边界](https://learn.chatgpt.com/docs/permissions)
- 若现有部署依赖透明代理，必须确认容器默认路由、DNS、fake-IP 与 IPv6 的实际去向；OpenClash 在同一 NAS 上运行并不能证明容器流量经过它。首版优先显式代理，避免叠加两种路径造成回环或排障混淆。
- 保持 TLS 证书校验。只有确有自建 CA 时才配置受信 CA，不用关闭校验解决问题；代理认证信息不写进 Git、镜像或前端。代理日志也要脱敏，不记录模型输入、认证信息或带 Key 查询参数。
- 需要代理的能力遇到代理不可达时应明确失败，不静默直连或换账号重试。该行为写入验收；具体超时、重试次数、限流与并发参数在实施时说明并确认，不在规划中拍定数值。

### 音频适配与入口防护

- 现有 `canvas-proxy` 是无鉴权的通用 CORS 转发器，并非 OpenClash 的替代品。NAS 不公开它，也不简单在同源反代下挂载任意 URL 转发路径。
- 音频 API 由用户在服务端配置受控 adapter，普通请求只提交业务参数，不提交任意目标 URL 或认证头。只允许配置过的目标与协议，限制目标 IP、重定向和外部资源下载，防止访问 NAS/OpenWrt 管理端等内部服务；代理端也需落实相应目的限制，不能依赖一次 DNS 检查。
- 不把应用登录 Cookie、内部身份头、客户端 Authorization 或上游 Set-Cookie 原样透传；适配器只构造供应商需要的请求头并注入对应 Key。原浏览器任意调用脚本不能原样搬到持 Key 的服务器上，供应商差异由审定的适配处理。
- LAN 入口使用可信 HTTPS，并限制 IPv4/IPv6 入站范围；不配置公网端口转发或 UPnP 暴露。Docker 发布端口默认可能绑定所有宿主地址，应显式选择接口并核对实际防火墙路径。[Docker 端口发布](https://docs.docker.com/engine/network/port-publishing/)
- 反代保持 SSE 流式传输，不缓存私有事件和产物。长连接相关设置在验证后定稿，不以无限超时掩盖断线问题。

### 前端分流

- 在 `web/src/services/api/` 增加小型生成分流模块，统一请求 NAS 同源服务；复用现有数据转换，不引入通用插件框架。NAS 版引入真实后端，音频不再遵循原静态站浏览器直接持 Key 请求的方式。
- 按能力确定后端：对话/文本/图片走 Codex，音频走独立 API，视频暂未接入。不用一个全局开关将所有能力切到 Codex；音频和视频分别保留自己的渠道及模型选择。
- Codex 路径在 API Key、Base URL、渠道模型校验之前完成分流，不使用假 Key 或假渠道绕过校验。缺少音频或视频 Key 不得阻塞对话、文本或图片。
- 覆盖画布生成、重新生成、生图工作台、文本/图片问答及 `web/src/pages/canvas/hooks/use-plugin-host.tsx` 的生成入口。
- 保留现有结果类型、流式文本回调和存储流程；Codex 的模型选择来自实际运行时，音频模型来自用户配置的 API 渠道。模型出现在列表中不代表账户必然能完成推理。
- 只有经验证支持的参数才显示为可用；图片数量、尺寸、质量需适配 Codex 实际能力，音频的音色、语速、格式继续按所接 API 的支持情况处理。
- 音频 Key 仅由 NAS 服务端保管，不发送给浏览器或 Codex；未配置时仅音频生成不可用。视频未接入时不自动选用其他渠道，不删除既有媒体或清空既有凭据。
- 能力状态区分“未验证”“可用”“不可用”，展示原因。诊断只读，真实生成验证由用户主动发起，避免连接时自动消耗额度。

### 任务和会话

- 独立生成任务有稳定任务 ID，绑定来源设备/页面、画布、目标节点与对应 `threadId`、`turnId`；产物再绑定 `itemId` 和产物 ID。不新增用户 owner 字段。这是项目内部契约，需在实现阶段定稿，不是假设 Codex 已有同名 API。
- 生图工作台与插件入口绑定各自目标，不依赖侧边栏当前是否展开，也不复用侧边栏 `activeThreadId`。
- 生成任务使用独立线程，复用 app-server 客户端；先沿用现有串行执行方式。独立线程本身不能解决队列自等待，必须同时移除递归调用路径。
- 注入 MCP 工具时，排除会重新发起 Codex 文本/图片生成的工具；侧边栏 Agent 直接用自身文本/内置生图能力，然后写入结果。浏览器按钮才提交独立 Codex 生成任务。保留经独立 API 执行的音频工具，不因禁止递归而一并屏蔽；视频未接入时返回明确不可用状态。现有工具分派端也检查来源，不能只靠提示词禁止递归。
- 任务展示待处理、运行、等待批准、成功、失败、取消等必要状态。只有成功终态且结果可读取才报告生成成功。
- 用户取消应作用于对应任务；未开始的任务可撤销，运行中的任务映射到该 turn 的中断。晚到结果不得覆盖取消状态或其他任务。
- 对话消息继续按 `threadId + turnId + itemId` 归属；权威历史与实时补充沿用既有规则。首版避免改消息存储格式；若必须升级，按项目要求先备份再迁移，独立管理协议版本和存储版本。

### 产物交付

- 复用 `image_generation`、`savedPath` 的明确输出契约；NAS 通过任务 artifact 接口交付，关闭原 `/agent/local-image` 任意路径入口，替换递归扫描字符串的做法。
- 路径规范化与校验放在 Node 端，以 NAS Linux 文件路径为主，保留 Windows 开发场景；限定为本任务登记的产物，校验解析后的真实路径、文件类型和所属任务。
- 浏览器通过同源认证接口和产物标识读取文件，不能指定 NAS 绝对路径。内部 Agent token 仅服务端使用，Codex 登录凭据不进入浏览器业务存储或日志。
- 复用 `uploadImage` / `uploadMediaFile` 将产物存入浏览器 localforage；节点保存现有存储引用，不把本地文件路径或短期 URL 当持久资产。
- 同一任务的同一产物只导入一次；产物清单和导入确认可恢复。浏览器存储成功后再确认，不因实时事件重放重复新增节点。
- 任务启动时固定目标。生成期间切换画布、关闭标签或删除节点，不得把结果写入另一个画布；原目标不可写时保留待接收结果并提示用户。
- 断线后查询已有任务和产物，不能自动重跑付费生成。Agent 重启后先核对 Codex 历史与产物；无法确认完成时显示中断/待确认，由用户决定是否重试。
- 生成失败、文件读取失败、浏览器入库失败分别提示；后两类优先重新交付已生成产物。

## 实施拆分与验收

取消成员权限隔离后，实施范围简化为单用户入口、凭据保护、任务交付与 NAS 网络接入。工期仍在 P0 核实实际运行环境后估算，不沿用未经 NAS 验证的旧估算。

| 阶段 | 改动范围 | 退出条件 |
| --- | --- | --- |
| P0 NAS 可行性 | 实际 CPU 架构、容器运行时、CLI/沙箱、设备登录、OpenClash 与 HTTPS 入口 | 确认实际运行时可用；区分认证、代理、权限与生图能力问题；诊断不输出认证缓存中的凭据 |
| P1 单用户部署与保护 | NAS 编排、单用户入口认证、secret 挂载、受控音频适配入口 | 未认证访问被拒绝；内部服务不可绕过入口直连；浏览器不获取 Codex 凭据或音频 Key；无成员/角色体系 |
| P2 对话与文本 | 生成分流、Codex 任务管理、画布与插件文本入口 | 不配置浏览器 Key 即可对话/生成文本；流式输出、取消、归属正确；无递归排队 |
| P3 内置生图 | 图片任务、产物导入、画布及工作台 | 文生图与参考图编辑可用；NAS 产物交付任务绑定的指定目标 |
| P4 恢复与交付 | 持久化、断线恢复、代理诊断、备份说明、定向回归 | 容器重建和断线不重复生成；代理故障不静默直连；音频独立配置、视频暂不接入 |

P0 不能确认 app-server 生图时，记录图片迁移的阻塞原因，先推进对话与文本；图片仍列为未完成，不宣称已迁移，也不自动改用浏览器自动化或私有接口。

P0 同时判断是否需要调整锁定的 CLI 版本；不必为了跟随 PATH 版本而升级。生成项目实际版本的协议定义后，仅适配本项目用到的字段。

定向验收至少覆盖：

1. 浏览器不配置 API Key，侧边栏普通对话、文本节点和图像问答按已验证能力正常工作；不会弹出无关渠道必填提示。
2. 同一个提示词从画布和生图工作台发起，均经 Codex 生成；请求追踪中没有旧 `/images/*`、`/responses` 或模型脚本调用。该标准针对项目浏览器调用，不要求 Codex 本身离线。
3. 参考图编辑使用原始图片并保留来源关系；输出比例来自真实产物，不强行拉伸。
4. Windows 路径、空格、中文文件名可交付；未登记文件、路径越界和错误目标被拒绝。
5. 生成中刷新、断连重连、切换画布，最终产物只导入原目标一次；删除原节点不会导致写到其他节点。
6. 取消、登录失效、额度不足、模型不可用、文件丢失、入库失败有明确状态；重试交付不会重新生成。
7. Codex 通过工具请求生成时不会等待自身队列；已有审批、历史归属及多页面路由保持正确。
8. 未配置音频 API 时仅音频生成不可用，对话/文本/图片不受影响；配置后只有音频请求使用该渠道，音频工具不会递归调用 Codex。
9. 视频保持暂未接入状态，不发起生成或自动使用其他渠道；现有代码、配置入口及媒体保留，以便后续接入其他 API Key。
10. 未认证不能访问 API/SSE/媒体和管理入口；已认证设备可使用同一应用空间，不增加成员隔离。多标签页的审批、取消和产物仍定位到正确任务；生成请求不能绕过服务端执行权限配置。
11. 浏览器存储、网络响应和导出不含 Codex 缓存/音频 Key；代理与反代日志不含 token、Cookie 或 query key。恶意目标 URL、重定向和路径越界被拒绝。
12. 从实际 worker 与音频适配进程分别验证 OpenClash 连通、TLS、登录刷新、流式输出和产物下载；仅 NAS 宿主 curl 成功不能作为容器验收。内部 MCP/服务请求不经过出站代理。
13. OpenClash 停止时依赖代理的请求明确失败，恢复后不重复提交已完成任务；设备登录失败与网络失败分开提示。
14. 容器重建保留账号状态和任务/产物归属；IPv4/IPv6 均只能从预期入口访问。现有画布仍按浏览器保存，未实现的跨设备同步不计为完成。

实现已做与这些行为对应的本地定向验证，再交用户手动验收；遵循项目规则，未执行构建或类型检查，也未运行真实模型生成。实际 NAS 验收仍按上述退出条件执行。
